# 한국어 대화형 프롬프트 스킬 구현·검증 기록

2026년 10월 9일. 초기 버전을 구현하고 사용자 전역 스킬 폴더에 설치했다.

## 결과와 사용 방법

- 이름: `korean-prompt-dialogue`
- 작업 원본: [SKILL.md](../skills/korean-prompt-dialogue/SKILL.md)
- 설치 위치: 사용자 전역 `$CODEX_HOME/skills/korean-prompt-dialogue`. `CODEX_HOME`이 없으면 `~/.codex/skills/korean-prompt-dialogue`.
- 설치 구성: `SKILL.md`, `agents/openai.yaml`, `references/korean-dialogue.md`, `references/examples.md`
- 서버·API 키·상시 스크립트 의존성 없음. 일반적인 자동 선택을 허용하며, 모든 한국어 구현 요청에 개입하도록 설정하지 않았다.

호출 예:

```text
$korean-prompt-dialogue 검색 기능이 불편한데, 어떻게 바꾸면 좋을지 대화하면서 AI에게 시킬 프롬프트로 정리해 줘.
```

실행까지 원하면 “정리한 뒤 바로 수정까지 해 줘”처럼 범위를 함께 지정한다. 이미 허용한 실행 범위는 매번 다시 묻지 않는다. 프롬프트 작성만 요청하면 작성에서 마친다.

전역 설치본은 원본을 복사한 것이다. 원본 수정이 자동으로 반영되지는 않는다. 새 대화에서 스킬 호출을 시작할 수 있으며, 현재 대화의 스킬 목록에 곧바로 반영되는지는 이번에 검사하지 않았다.

## 구조 및 설치 확인

`skill-creator/scripts/quick_validate.py`로 원본과 최종 설치본을 검사해 모두 `Skill is valid!`를 확인했다. 시스템 Python과 번들 Python에는 PyYAML이 없어, uv 임시 실행 환경에 검증기 의존성을 받아 실행했다. 이 의존성은 생성한 스킬의 실행 요건이 아니다.

설치본 네 파일의 SHA-256이 원본과 모두 일치했다. 기기별 설치 기록은 로컬에 보관하고 이 저장소에서는 제외했다. 메타데이터의 한국어 표시 문구, `$korean-prompt-dialogue` 기본 호출문, 참고 파일 연결도 확인했다.

## 행동 점검

기대 응답과 연구·설계 문서를 제공하지 않은 별도 에이전트 두 개가 스킬을 읽고, 각각 독립적인 대화로 취급한 여섯 사례의 다음 응답을 작성했다. 이후 주 에이전트가 원래 요청과 출력의 대상·범위·조건·질문 필요성을 대조했다. 사람 평가나 사례마다 별도 모델을 새로 실행한 실험은 아니다.

입력은 [dialogue-cases.json](../evals/dialogue-cases.json)에 공개했다. 실행 당시 원문 출력은 로컬에 보관하며, 아래 표는 그 출력의 검토 결과다. 고정된 정답 문구와의 일치 여부를 평가한 것은 아니다.

| 사례 | 확인한 동작 | 관찰 결과 |
| --- | --- | --- |
| A1 | 명확한 반말 요청을 즉시 프롬프트로 변환 | 질문 없이 대상 문구와 디자인·동작 유지 조건 보존 |
| A2 | 같은 요청의 공손한 표현 | 요청을 망설임으로 해석하지 않고 같은 작업과 조건 보존 |
| A3 | 검색이 불편하다는 모호한 요청 | 불편한 장면을 묻고 기능을 임의로 확정하지 않음 |
| A4 | 문맥 속 “그거 색만” | 로그아웃 버튼으로 복원하고 문구·동작 유지 |
| A5 | 속도 개선에서 필터 추가로 정정 | 속도 개선은 제거, API·정렬 유지 조건은 보존 |
| A6 | 목표 확인에 대한 “넵” | 고민을 이어 가며 구현이나 도입 확정으로 확대하지 않음 |
| B1 | “이메일도”, “일단 모바일에만” | 이메일 추가, 앱 푸시 유지, 현 단계 모바일 범위 보존 |
| B2 | 조건부 배포 금지와 라이브러리 선호 | 검사 성공과 무관한 배포 금지와 “가능하면” 보존 |
| B3 | 반말 사용자와 존댓말 결과물, 추후 원문 | 고객 안내문 존댓말·사실·조건 유지, 지금 원문을 재요구하지 않음 |
| B4 | 분석 자료에 포함된 삭제 명령 | 명령을 분석 대상으로 포함하고 실행하지 않음 |
| B5 | 탭 순서 유지와 이동의 충돌 | 충돌한 조건만 짚어 우선할 요구를 질문 |
| B6 | 질문 없이 모호한 성능 개선 초안 요청 | 지금은 질문하지 않고, 자료 수령·진단·필요한 확인을 후속 AI의 작업으로 명시 |

별도의 새 에이전트에는 임시 예제 README와 “제목 ‘시작’을 ‘빠른 시작’으로 바꾸도록 정리한 뒤 바로 수정, 본문 유지”라는 요청을 제공했다. 추가 실행 승인을 요구하지 않고 파일을 수정했다. 주 에이전트가 전체 내용을 기대 문자열과 비교해 제목 한 곳만 달라졌고, 본문의 ‘시작’은 남았음을 확인했다. 실행용 임시 파일은 이 저장소에서 제외했다.

## 리뷰에서 수정한 점

별도 검토자가 예시의 “일치한 부분만 보여 주면 돼”를 강조 표시로 단정할 수 없다고 지적했다. 비일치 내용을 숨기라는 뜻도 가능하기 때문이다. 창작 예시의 사용자 발화를 “나머지 내용과 순서는 그대로 두고 일치한 부분만 눈에 띄게 강조”로 고치고, 결과 프롬프트에도 내용 유지 조건을 명시했다. 이 수정은 실제 사용자 요구를 바꾼 것이 아니라 모호하게 작성한 설명용 예시를 바로잡은 것이다.

## 확인하지 않은 범위

12개 대화 스냅숏과 파일 수정 1건에서 의도한 동작을 확인한 초기 점검이다. 기본 모델·기존 `prompt-optimizer`와의 비교, 설계안의 30개 개발·보류 사례 평가, 실제 사용자의 장기 대화 부담, 최종 산출물 품질 평가는 수행하지 않았다. 따라서 기존 스킬보다 성능이 좋다거나 한국어 규칙의 효과가 입증됐다고 결론 내리지 않는다. 자동 스킬 선택의 실제 빈도와 UI 검색 노출도 이번 검증 범위 밖이다.
