# 한국어의 특성과 대화를 통한 프롬프트 구체화 연구

2026년 10월 9일 기준 공개 자료 조사. 목적은 한국어 대화에서 사용자의 생각을 구체화하고 실행용 프롬프트로 옮기는 스킬의 설계 근거를 마련하는 것이다.

한국어에 맞춘 설계의 핵심은 **조사·어미·생략·높임말이 대화 맥락에서 전달하는 의미를 보존하는 것**이다. 공손한 말투를 늘리는 것만으로는 충분하지 않다. 사용자가 확정한 내용과 탐색 중인 생각을 구분하고, 필요한 대화를 통해 원하는 결과와 조건을 드러내야 한다. 이를 잘 수행하는 스킬이 실제 결과의 품질을 높이는지는 후속 평가가 필요하다.

## 조사 범위와 근거의 구분

형태·통사·의미, 높임법, 화용과 대화 문화, 디지털 한국어, 대화와 AI에 관한 연구를 함께 살폈다. 발음·문자사·방언 체계 전체를 망라하기보다 요청의 해석과 프롬프트 작성에 직접 영향을 주는 부분을 깊게 다룬다. 한국어 사용자는 국적·연령·지역·직업·모어가 서로 다르므로, 한국어를 쓴다는 사실만으로 개인의 문화적 성향을 정하지 않는다.

아래에서 **언어학적 사실과 관찰**은 기관 자료나 연구가 설명하는 현상, **AI 실험 결과**는 특정 모델과 과제에서 확인된 결과, **설계 제안**은 이 프로젝트에 적용하기 위해 도출한 가설이다. 자연대화 연구의 결과가 곧 현재 AI의 행동이나 스킬 성능을 입증하는 것은 아니다. 초록만 확인한 연구는 그 범위 안에서만 사용했으며 [출처 문서](sources.md)에 표시했다.

강수진의 『지적 대화를 위한 AI 언어 수업』은 이 프로젝트의 문제의식과 연결된다. 공개 소개와 목차에는 협력, 턴 주고받기, 수정, 조사, 완곡 표현, 높임법이 포함된다. 다만 이번 조사에서 확인한 것은 출판사가 제공한 소개·목차·일부 발췌이며 책 전체의 논증을 검증한 것은 아니다. 책의 관점을 출발점으로 삼되 언어학적 설명과 AI 성능 주장은 각각 별도 근거로 판단한다. [출판유통통합전산망의 도서 소개](https://bnk.kpipa.or.kr/home/v3/addition/adiPromoMetaDataView02/seq_20260508050354712148)

## 한국어 구조가 요청의 의미에 미치는 영향

### 조사와 어미에 담기는 정보

한국어는 조사와 어미 같은 문법 요소가 결합하는 교착적 특성을 가진다. 기본 어순은 주어·목적어·서술어이지만 변이가 가능하며 그 변이에도 제약이 있다. 따라서 핵심 명사와 동사만 남기면 문장 역할, 조건, 부정, 요청 방식이 사라질 수 있다. 서술어가 뒤에 오는 문법적 특성만으로 한국어 사용자의 글이 늘 미괄식이라고 결론 내릴 수는 없다. [국립국어원 교사 연수 교재의 한국어 특징, 인쇄면 101–102쪽](https://www.korean.go.kr/common/download.do?c_file_name=71667217-29f9-41c8-92e9-e2f12b5b5657_0.pdf&file_path=etcData&o_file_name=%EC%82%AC%ED%95%A0%EB%A6%B0+%ED%95%9C%EA%B5%AD%EC%96%B4+%EA%B5%90%EC%82%AC+%ED%95%9C%EA%B5%AD%EC%96%B4+%EC%97%B0%EC%88%98+%EA%B5%90%EC%9E%AC.pdf)

격조사는 문장 안의 역할을 표시하고, 보조사는 한정·추가·대조 등의 의미에 관여한다. `은/는`은 문맥에 따라 주제 제시나 대조 등에 쓰이므로 항상 배타적인 한정을 뜻하지 않는다. `만`과 `도`를 지우거나 서로 바꾸는 것은 단순한 문장 다듬기가 아니다. [유동석, 2004, 조사](https://www.korean.go.kr/nkview/nklife/2004_1/2004_0112.pdf)

| 관찰할 부분 | 직접 만든 예 | 프롬프트 작성에 필요한 판단 |
| --- | --- | --- |
| 격과 역할 | 서버가 클라이언트를 호출해 / 서버를 클라이언트가 호출해 | 단어의 나열 순서만으로 행위자를 정하지 않는다. |
| 한정과 추가 | 제목만 바꿔 / 제목도 바꿔 | 수정 범위 제한과 기존 요구에 대한 추가를 구분한다. |
| 주제와 배타성 | 검색은 고쳐 줘 / 검색만 고쳐 줘 | 첫 문장만으로 다른 기능의 수정 금지를 만들어 넣지 않는다. |
| 조건과 양보 | 통과하면 실행해 / 통과해도 실행하지 마 | 조건 뒤의 실제 행위와 부정을 함께 읽는다. |
| 시점과 단계 | 지금은 정리만 해 / 정리한 다음 구현해 | 현재 작업과 후속 작업의 경계를 보존한다. |
| 상태와 의향 | 바꿨어 / 바꾸고 싶어 | 현재 상태 보고와 원하는 변화를 구분한다. |
| 선호와 필수 | 가능하면 유지해 / 반드시 유지해 | 조건의 강도를 임의로 강화하거나 약화하지 않는다. |

이 표는 문법을 규칙 엔진으로 구현하자는 제안이 아니다. 현대 모델의 언어 이해를 활용하되, 재작성 과정에서 손실되기 쉬운 의미를 확인하는 항목으로 삼자는 제안이다.

### 생략과 지시 대상

한국어에서 명시되지 않은 주어·목적어를 이해할 때 문법 위치뿐 아니라 앞뒤 절의 담화 관계가 중요하다. Song과 Kaiser의 두 실험에서는 연결 표현과 추가 표지가 생략 대명사의 해석에 영향을 주었다. 해당 조건에서는 주제 표지의 효과가 나타나지 않았으므로 `은/는` 하나로 생략 대상을 찾는 규칙을 만들 수 없다. [Song와 Kaiser, 2020](https://journals.linguisticsociety.org/proceedings/index.php/PLSA/article/view/4751)

**설계 제안:** “그거”, “그 부분”, “아까처럼”은 앞선 대화나 확인 가능한 화면·파일에서 대상을 찾는다. 후보가 하나로 충분히 정해지면 질문하지 않는다. 여러 후보가 남고 수정 결과가 달라질 때만 특정한다. 자연스러운 조사 생략을 문법 오류로 취급해 사용자에게 완전한 문장을 요구하지 않는다.

“우리 서비스”의 `우리`도 실제 조직, 사용자 집단, 공동 작업물 등 무엇을 가리키는지 문맥에서 확인해야 한다. 다만 `우리`라는 단어만으로 공동 소유, 모든 구성원의 동의, 특정 조직 문화까지 추정하는 것은 설계상 허용하지 않는 편이 타당하다. 이는 개인의 권한과 의도를 과장하지 않기 위한 제안이지 `우리`의 모든 언어적 용법을 설명하는 규칙은 아니다.

### 부정과 적용 범위

한국어 부정의 해석은 수량 표현과 초점 표지에 따라 달라질 수 있다. 특정 구문을 분석한 의미·통사 연구도 이 상호작용을 다룬다. “모든 항목을 바꾸지는 마”와 “어떤 항목도 바꾸지 마”는 같은 제약으로 재작성할 수 없다. [Park와 Dubinsky, 2020](https://journals.linguisticsociety.org/proceedings/index.php/PLSA/article/view/4670)

**설계 제안:** 원하는 변화와 함께 금지, 유지 조건, 예외, 적용 범위를 보존한다. 부정을 긍정 표현으로 풀어 쓰는 것은 도움이 될 수 있지만 원래 금지를 삭제해서는 안 된다. “검색 방식은 바꾸지 말고 결과 표시만 고쳐”는 결과 표시 수정과 검색 방식 유지라는 두 조건을 함께 담는다.

## 높임말과 경어체

### 누구를 높이는지 구분하기

높임법은 하나의 공손도 척도가 아니다. 교육 문법에서는 주체 높임, 객체 높임, 상대 높임을 구분한다. 주체 높임과 객체 높임은 문장에 등장하는 사람에 관한 것이고, 상대 높임은 말을 듣는 사람에 관한 것이다. 격식성 또한 높임 정도와 완전히 같은 축이 아니다. [국립국어원, 독서 능력 향상을 위한 문법 내용 개발, 인쇄면 78쪽](https://www.korean.go.kr/common/download.do?book_seq=162&c_file_name=556c8d1f-c239-408e-9199-94a4a42eedb1_0.pdf&downGubun=bookDataView&file_path=bookData&o_file_name=%EA%B5%AD%EC%96%B4%EB%8A%A5%EB%A0%A5-01-15.pdf)

| 구분 | 무엇을 높이는가 | 대표적인 수단 | 창작 예 |
| --- | --- | --- | --- |
| 주체 높임 | 문장 주어가 가리키는 대상 | `-시-`, `께서`, 높임 어휘 | 선생님께서 자료를 주셨어요. |
| 객체 높임 | 행위가 향하는 대상 | `께`, `드리다`, `여쭙다`, `뵙다` | 제가 선생님께 자료를 드렸어요. |
| 상대 높임 | 현재 발화를 듣는 사람 | 종결어미 | 담당자가 안내했어요 / 안내했습니다. |

같은 문장에 여러 높임이 함께 나타날 수 있다. “사용자에게 공손하게 답하라”는 지침과 “상사에게 제출할 보고서를 작성하라”는 지침은 서로 다른 대상을 고려한다. 최종 프롬프트에서는 대화 상대와 결과물 독자를 따로 파악할 필요가 있다.

### 말끝의 격식과 높임

국립국어원 한국어기초사전은 상대 높임이 주로 종결어미로 표현되며 해라체·하게체·하오체·합쇼체·해체·해요체 등을 구분한다고 설명한다. 해체와 해요체는 비격식체에 속한다. 이는 반말과 존댓말이라는 두 범주만으로 실제 말투를 모두 설명하기 어렵다는 기초가 된다. [국립국어원 한국어기초사전의 상대 높임법](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=92485)

| 대표 말투 | 예 | 스킬에서의 고려 |
| --- | --- | --- |
| 해요체 | 정리해 드릴게요. | 편안한 대화의 기본 후보. 사용자의 선호가 우선이다. |
| 하십시오체 또는 합쇼체 | 정리하겠습니다. | 공식적 안내나 보고의 후보. 항상 더 정확한 답을 만든다는 근거는 없다. |
| 해체 | 이렇게 정리하면 돼. | 친근한 대화의 후보. 사용자의 반말을 자동으로 따라야 하는 것은 아니다. |
| 해라체 | 다음과 같이 정리한다. | 설명문이나 지시문에서 쓰일 수 있다. 모든 용례를 무례한 대우로 해석하지 않는다. |
| 하게체·하오체 | 검토하게 / 검토하오. | 특정 관계·장르·인물 표현에 필요한 경우 다룬다. 일반 대화의 기본으로 고정하지 않는다. |

위 표는 주요 말투를 이해하기 위한 예시이며 모든 시대·장르의 높임 체계를 완전하게 열거한 표가 아니다. 기본 말투를 해요체로 두자는 선택은 이번 스킬의 제품 가설이며 연구로 입증된 최적값이 아니다.

### 공손함과 요청의 강도

한국어 요청의 공손성은 직접성 하나로 결정되지 않는다. Byon의 연구는 원어민 50명의 담화완성형 응답에서 높임과 간접성을 함께 분석했다. 다만 자연대화 빈도를 측정한 연구는 아니며 현재 AI 대화의 최적 문체를 증명하지 않는다. [Byon, 2006, 출판사 초록](https://www.degruyterbrill.com/document/doi/10.1515/PR.2006.013/html?lang=de)

“이 기능은 꼭 유지해 주시면 좋겠어요”에는 공손함과 강한 조건이 함께 있다. `좋겠어요`만 보고 선택 사항으로 약화하면 의도가 손실된다. 이미 수정 맥락이 분명한 “문구를 바꿔 주실 수 있을까요?”를 매번 능력 확인 질문으로 처리하는 것도 부자연스럽다. 반대로 아이디어를 탐색하는 “자동 저장도 있으면 좋을 것 같은데”는 현재 대화의 목적에 따라 제안일 수 있다.

**설계 제안:** 요청의 강도, 확정 여부, 공손함을 별도로 판단한다. 문장 하나의 어미만 보고 실행 여부를 결정하지 않는다. 공손하게 반박하거나 모순을 지적하는 것도 가능해야 하며, 자연스러운 존댓말을 무조건적인 동조로 구현하지 않는다.

## 한국어 사용자의 대화 문화와 다양성

### 관계와 상황이 함께 만드는 말투

나이, 직위, 친밀도, 공식적 역할은 언어 선택의 맥락이 될 수 있다. 그러나 같은 화자가 같은 대화에서도 말투를 바꾼다. Kim의 구어 말뭉치 연구는 비높임에서 높임으로의 전환이 존중뿐 아니라 대립적 태도나 인식적 거리에도 관여함을 보고한다. 존댓말을 언제나 친절이나 동의의 신호로 단정할 수 없다. [Kim, 2022, 출판사 초록](https://benjamins.com/catalog/kl.20010.kim)

따라서 문화적 설명은 “한국인은 원래 간접적이다”보다 **누가 누구에게, 어떤 상황에서, 어떤 목적과 매체로 말하는가**에 초점을 맞추는 편이 적절하다. 이번 연구들은 일부 상황의 사용 양상을 보여 주며, 국민 전체가 동일한 가치관이나 대화 습관을 가진다는 근거가 아니다. 스킬에는 문화적 전형보다 사용자 개인이 실제로 밝힌 목적과 선호를 우선한다.

### 상대의 반응을 유도하는 표현

`-는데`는 배경 설명에만 쓰이는 것이 아니다. 자연대화에서는 뒤에 주절이 오지 않은 채 상대의 반응을 유도하거나 요청·이견·거절을 수행하는 데 쓰일 수 있다. [Park, 1999, 출판사 초록](https://www.sciencedirect.com/science/article/pii/S0378216698000605)

또 한국어 확인 요청을 다룬 자연대화 연구는 종결어미와 부정 등의 형식이 앞선 대화와 결합해 확인 행동을 구성함을 보여 준다. 연구 자료가 특정 집단의 대면 대화라는 점과 텍스트에는 억양이 없다는 점을 고려해야 한다. [Kim, 2024, 공개 논문](https://d-nb.info/1335129375/34)

**설계 제안:** “결과가 너무 많은데요”가 단순 보고인지 개선 요청인지는 대화 목적을 함께 본다. 개선 요청이라 해도 자동으로 필터 추가나 결과 삭제를 결정하지 않는다. 사용자가 무엇을 어려워하는지 드러낼 질문을 고른다.

### 맞장구와 동의의 범위

온라인 대화의 `넵`을 분석한 연구에서는 긍정·수락·동의 외에도 수신 확인, 대화 지속, 상대 발화의 수정 개시 같은 기능이 보고됐다. 특정 표지의 연구를 모든 응답어에 동일하게 일반화할 수는 없지만, 직전 발화와 분리해 단순 승인 토큰으로 취급하기 어렵다는 점은 분명하다. [Ahn과 Yap, 2025, 연구기관의 논문 초록](https://en.semiosis.co.kr/?p=1556)

“설명이 이해되셨나요?”에 대한 “넵”은 이해 확인이고, “정리한 내용으로 수정할까요?”에 대한 “넵, 모바일은 그대로요”는 그 범위의 진행과 조건 추가로 읽힌다. 이는 창작한 대조 예시다. **설계 제안:** 짧은 응답이 어떤 질문에 답했는지 연결하고, 한 번의 응답으로 여러 미해결 선택을 동시에 확정하지 않는다.

### 디지털 한국어와 언어 혼용

온라인 육아 커뮤니티를 다룬 연구는 변이 어미와 연령 집단에 따른 사용 차이를 보고한다. 이처럼 디지털 한국어에는 정형적인 높임 표현 외에도 변이가 존재하지만, 특정 커뮤니티의 결과로 모든 한국어 사용자를 설명할 수 없다. [박채희, 2025, KCI 초록](https://www.kci.go.kr/kciportal/mobile/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003230402)

한국어와 영어의 혼용도 단순한 어휘 부족으로 볼 수 없다. 해외 한국인 학생들의 Facebook 대화를 분석한 연구에서는 인용, 대상 지정, 유대 형성 등 여러 기능이 보고됐다. 플랫폼과 집단이 제한된 연구다. [송경숙, 2014, KCI 초록](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART001854231)

**설계 제안:** `ㅋㅋ`, 축약, 비표준 표기 때문에 요청의 중요도를 낮추지 않는다. `flow`, `API`, 함수명 등을 불필요하게 순화해 대상이 달라지게 하지 않는다. 말투에서 나이·성별·성실성을 추정하지 않는다. 방언이나 한국어 학습자의 표현은 이해에 필요한 범위에서 다루며, 표준어 교정을 매번 대화의 선행 조건으로 삼지 않는다.

### 감각적인 평가 표현

“답답해”, “깔끔하게”, “툭툭 끊겨”, “쫀쫀하게” 같은 표현은 실제 불편이나 선호의 출발점이 될 수 있다. 이런 표현을 UI 수치나 문장 길이로 옮기는 데에는 작업 맥락이 필요하다. 의성·의태어의 문장 기능에 관한 국립국어원 자료는 관련 언어 현상을 설명하지만, 특정 UI 속성으로 치환하는 방법을 입증하지는 않는다. [채완, 1993, 의성어·의태어의 통사와 의미](https://www.korean.go.kr/nkview/nklife/1993_2/3_3.html)

**설계 제안:** 감각적인 표현을 지우기보다 실제 불편 장면이나 비교 예를 묻는다. “답답하다”를 언제나 느린 성능으로, “깔끔하다”를 언제나 정보 삭제로 바꾸지 않는다. 원래 표현을 품질 목표로 남기면서 합의한 관찰 기준을 덧붙일 수 있다.

## 대화를 통해 생각을 발전시키는 원리

### 현재 목적에 충분한 이해 만들기

Clark와 Brennan의 공동 기반 이론은 대화를 참여자들이 서로 이해를 맞추는 활동으로 설명한다. 기준은 모든 것을 완전히 공유하는 것이 아니라 현재 목적에 충분한 이해를 확보하는 것이다. 발화, 확인, 지연, 오류, 수정에 드는 양쪽의 노력도 고려한다. [Clark와 Brennan, 1991](https://web.stanford.edu/~clark/1990s/Clark%2C%20H.H.%20_%20Brennan%2C%20S.E.%20_Grounding%20in%20communication_%201991.pdf)

**설계 제안:** 생각 정리는 고정된 설문을 완주하는 과정이 아니다. “검색을 편하게”라는 말에서 “검색 속도”, “입력 부담”, “결과 가독성” 중 무엇이 문제인지 짧게 비교하면 사용자가 자신의 기준을 발견할 수 있다. 이미 분명한 요청에서는 이 대화를 생략한다. 인간 대화 이론만으로 AI의 최적 질문 수를 정할 수는 없다.

### 정정과 관점 변경 수용하기

한국어 자기수정 연구는 발화 뒤쪽의 조사나 어미를 바꾸는 행동이 내용과 관계를 조정하는 자원임을 다룬다. 이번 조사에서는 해당 연구의 대학 공개 초록과 서지 정보를 확인했다. 구어 연구를 텍스트 대화에 적용하는 것은 별도의 설계 해석이다. [Kwon과 Kim, 2024, 대학 공개 정보](https://khu.elsevierpure.com/en/publications/self-repair-in-korean-conversation-initiating-repair-in-post-posi/)

**설계 제안:** “아니, 정확히는” 이후의 말을 새 요구사항의 단순 추가로 처리하지 않고, 무엇을 교체하는지 확인한다. 사용자 생각이 발전하면 목표도 바뀔 수 있다. 다만 한 부분의 정정을 이유로 기존의 다른 유지 조건까지 버리지 않는다.

### 명확화와 제안의 차이

“결과가 복잡해”에 대해 “항목 수가 많은가요, 각 항목의 내용이 많은가요?”라고 묻는 것은 의미를 확인하는 행동이다. “필터를 만들면 어떨까요?”는 해결책 제안이다. 둘 다 유용할 수 있으나 제안이 사용자 요구로 채택됐는지 구분해야 한다.

**설계 제안:** AI는 생각을 발전시키는 질문이나 대안을 제공하되, 확정된 요구·관찰된 사실·선택되지 않은 제안·남은 가정을 구분한다. 사용자가 표현하기 어려우면 두 개의 짧은 예시를 비교하게 할 수 있다. 비교 예를 보여주는 것이 실제 구현을 시작한다는 뜻은 아니다.

## AI 연구에서 확인되는 것과 아직 확인되지 않은 것

### 필요한 경우에만 묻는 정책

Zhang과 Choi는 질의응답·기계번역·자연어 추론에서 모호함을 확인할 시점을 연구하고, 최종 성능과 사용자 상호작용 비용을 함께 평가한다. 질문 생성이나 임의 길이의 다중 대화 전체를 해결한 연구는 아니다. [Clarify When Necessary, 2025](https://aclanthology.org/2025.findings-naacl.306/)

이 연구는 스킬에서도 질문 수만이 아니라 질문으로 얻은 결과와 비용을 함께 보아야 한다는 근거가 된다. “질문은 무조건 한 개”, “두 번이면 충분” 같은 수치는 이 논문에서 입증된 한국어 규칙이 아니다.

### 한국어 간접 화행 이해

Park 등의 사전 공개 논문은 같은 발화가 문맥에 따라 다른 행동을 수행하는 한국어 문항 240개로 모델과 인간 응답을 비교한다. 요청 기능을 수행하는 진술 등에서 어려움이 나타났다. 인간 참여자가 특정 연령·교육 배경에 제한되고 평가 모델도 정해져 있으므로 모든 한국어 사용자나 현재 모든 모델로 일반화할 수 없다. [Evaluating Large Language Models on Understanding Korean Indirect Speech Acts, 2025 사전 공개본](https://arxiv.org/html/2502.10995v1)

**설계 제안:** 같은 문장에 서로 다른 앞선 대화를 붙인 평가 사례를 만든다. 말끝이 비슷해도 탐색·평가·수정 요청을 구분하는지 확인한다. 영어나 한국어라는 언어 선택만으로 이해 성능을 단정하지 않는다.

### 공손함이 곧 정답률은 아니다

Jung 등의 연구는 수능·모의평가 객관식 113문항과 다섯 요청 표현을 사용했다. 저자가 설정한 공손성 단계에 대한 정답률 변화는 모델마다 달랐다. 표현을 바꾸면서 간접성·문장 구조도 함께 달라졌으므로 높임 등급만의 효과를 분리한 실험으로 보기 어렵다. [Are Large Language Models Affected by Politeness, 2024, 방법과 표 1·4](https://aclanthology.org/2024.paclic-1.86.pdf)

이 결과로 “존댓말일수록 정확하다”, “반말이 항상 좋다”, “미국 모델은 한국 문화를 이해하지 못한다”라고 결론 내릴 수 없다. 또한 답변 길이나 설명의 많고 적음을 실제 작업 품질과 동일하게 보아서는 안 된다.

### 문법적 높임과 사회적 적절성의 구분

Cho와 Kwon은 주체 높임 관련 형태의 예측 가능성을 여러 모델에서 평가했다. 형태적 불일치에 민감하면서도 사회화용적 제약을 충분히 반영하지 못하는 경향을 보고한다. 이는 특정 모델의 언어 처리 실험이며 최신 대형 상용 챗봇의 대화형 프롬프트 성능을 직접 평가한 것은 아니다. [Can Language Models Process Linguistic Deference, 2026](https://aclanthology.org/2026.scil-main.35/)

**설계 제안:** 높임 표지를 많이 넣는 검사와 자연스러운 대화인지를 평가하는 검사를 분리한다. 사회관계를 모르는 상태에서 직위나 연령을 만들어 높임을 조정하지 않는다.

### 한국어 요청을 의도 표현으로 바꾸는 선행 연구

Cho 등의 연구는 비정형 한국어 질문·명령을 의도 표현으로 변환하는 50,837개 자료를 구축했다. 현재 과제와 직접 연결되지만, 운율에 의존하는 발화와 수사적 용법 등은 제외했고 현대 LLM의 프롬프트 생성 스킬을 검증한 연구는 아니다. [Machines Getting with the Program, 2020](https://aclanthology.org/2020.findings-emnlp.31/)

특히 일부 금지와 요구가 함께 있는 문장의 주석에서는 긍정 핵심만 남긴다. 이것을 기존 기능 수정 요청에 그대로 적용하면 유지 조건을 잃을 수 있다. 따라서 해당 연구의 자료와 분류를 참고하되, 제약을 보존하는 별도 평가가 필요하다.

### 그럴듯한 문장보다 사용자 맥락에 맞는 결과

Malaviya 등의 연구는 평가에 사용자 의도·전문성·유용성 맥락을 제공하면 판단과 모델 순위가 달라질 수 있음을 보여 준다. 연구의 맥락이 합성된 것이므로 실제 사용자 검토를 대신하지는 못한다. [Contextualized Evaluations, 2025](https://aclanthology.org/2025.tacl-1.41/)

또 비전문가의 프롬프트 작성 과정을 살핀 CHI 연구는 한두 번의 결과를 일반화하는 등의 어려움을 관찰했다. 소규모의 이전 세대 모델 연구이므로 현재 모든 사용자의 능력을 설명하는 자료는 아니다. [Why Johnny Cannot Prompt, 2023](https://people.eecs.berkeley.edu/~bjoern/papers/zamfirescu-johnny-chi2023.pdf)

**설계 제안:** 스킬을 평가할 때 프롬프트의 유창함과 실제 결과의 적합성을 나눠 본다. 원래 사용자의 의도와 제약을 평가자에게 제공하고, 스킬 이름을 가린 상태에서 비교한다. 한국어 규칙을 추가해서 좋아진 것인지 단순히 대화를 더 해서 좋아진 것인지도 구분해야 한다.

## 설계용 대조 사례

아래 문장과 판정은 직접 만든 예시다. 연구 원문 인용이나 이미 검증된 평가 자료가 아니다. 앞선 대화에 따라 판정이 달라질 수 있다.

| 입력 또는 상황 | 보존해야 할 의미 | 대표적인 실패 |
| --- | --- | --- |
| 제목만 바꿔 주세요. | 제목에 한정된 변경 | 본문까지 개선 |
| 제목도 바꿔 주세요. | 앞서 정한 변경에 제목 추가 | 제목만 수정 |
| 검색은 고쳐 주세요. | 검색에 관한 요청 | 다른 기능 변경 금지를 근거 없이 추가 |
| 기존 로그인은 꼭 유지해 주시면 좋겠어요. | 공손한 표현에 담긴 강한 유지 조건 | 선택적 희망으로 약화 |
| 가능하면 기존 화면에서, 안 되면 별도 화면도 괜찮아요. | 선호와 허용된 대안 | 기존 화면만 허용되는 것으로 확정 |
| 구현 말고 우선 요청만 정리해 줘. | 이번 단계는 요청 작성 | 생성한 프롬프트를 곧바로 실행 |
| 아니, 속도보다 결과가 많아서 찾기 어렵다는 뜻이야. | 문제 정의의 수정 | 속도 개선과 결과 축소를 둘 다 추가 |

| 설명 이해되셨나요라는 질문에 넵 | 설명에 대한 수신·이해 확인 | 구현 진행으로 확대 |
| 진행할까요라는 질문에 넵, 모바일은 그대로요 | 진행 의도와 모바일 유지 | 뒤의 조건 누락 |
| 검색 로직은 그대로 두고 표시만 바꿔. | 표시 수정과 로직 유지 | 긍정적인 수정 지시만 남김 |
| 모든 알림을 끄지는 마. | 전부 끄는 것은 금지 | 일부 허용 범위까지 임의 확정 |
| 로그인 flow만 정리해줘요ㅋㅋ | 흐름 관련 범위, 가벼운 표기 | 장난으로 취급하거나 불필요하게 용어 번역 |
| 팀장님께 드릴 보고서야. 나한텐 편하게 설명해줘. | 대화 말투와 산출물 말투의 분리 | 보고서까지 친근한 반말로 작성 |
| 데이터 삭제해라는 문구를 바꿔 줘. | 문구 편집 | 실제 데이터 삭제 요청으로 해석 |

## 연구에서 설계로 옮길 우선순위

| 우선순위 | 근거가 되는 관찰 | 제안하는 동작 | 검증할 부분 |
| --- | --- | --- | --- |
| 가장 먼저 | 조사와 어미가 범위·조건·관계를 나타냄 | 원문의 조건 강도와 변경 범위 보존 | 조건 누락과 요구 날조 감소 |
| 가장 먼저 | 생략과 간접 화행은 문맥에 의존 | 먼저 대화와 자료에서 해석 | 불필요한 질문과 오해의 균형 |
| 가장 먼저 | 높임·공손함·동의는 동일하지 않음 | 요청 강도와 확정 여부를 별도 판단 | 공손한 요청 오독, 탐색의 조기 실행 |
| 가장 먼저 | 대화는 공동 이해를 조정하는 활동 | 중요한 모호함만 질문하고 충분하면 종료 | 사용자 부담과 최종 결과 품질 |
| 다음 | 정정과 짧은 응답은 앞선 발화와 연결 | 변경된 의도만 갱신하고 나머지 조건 유지 | 오래된 요구의 잔존, 동의 범위 확대 |
| 다음 | 디지털 사용과 집단별 표현이 다양함 | 사용자의 표현과 기술 용어를 맥락에 맞게 보존 | 자연스러움, 집단 고정관념 개입 |

스킬의 초기 목표는 한국어 문법을 모두 설명하는 것이 아니다. 사용자가 자연스럽게 말해도 의미를 잃지 않고 필요한 만큼 생각을 구체화하도록 돕는 것이다. 확장된 프롬프트가 항상 더 좋다는 가정을 두지 않고, 명확한 요청에는 짧은 결과를 내는 것이 적절한지 함께 평가한다.

후속 단계는 이 근거를 [설계 계획](skill-design-plan.md)의 간결한 대화 정책과 사례로 옮겨 구현하고 비교하는 것이다. 현재 산출물은 연구와 계획이며, 실제 스킬의 효과에 대한 검증 결과는 아직 없다.
