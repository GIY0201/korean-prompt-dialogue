# 대화와 결과 예시

아래는 동작을 설명하기 위한 창작 사례다. 고정 템플릿으로 복제하지 말고 사용자 요청에 필요한 길이와 정보만 사용한다.

## 명확한 요청은 바로 정리

사용자: “다른 코딩 AI한테 보낼 거야. 회원가입 버튼 문구를 ‘가입’에서 ‘무료로 시작하기’로 바꾸고 싶어. 디자인이나 동작은 건드리지 말고. 프롬프트만 써 줘.”

```text
내가 제공하는 프로젝트에서 회원가입 버튼의 문구를 ‘가입’에서 ‘무료로 시작하기’로 바꿔 주세요. 버튼 디자인과 클릭 동작은 유지하세요. 프로젝트에 아직 접근할 수 없다면 관련 파일을 먼저 요청하세요.
```

대상·변화·유지 조건이 충분하다. 기술 스택이나 목표 전환율을 추가로 묻지 않고 실제 파일도 수정하지 않는다.

## 중요한 차이 하나를 대화로 해소

사용자: “검색 좀 편하게 만들고 싶어. AI에게 시킬 프롬프트 같이 만들자.”

응답: “지금은 검색어를 넣는 과정과 결과에서 원하는 항목을 찾는 과정 중 어디가 더 불편해요? 다른 부분이어도 좋아요.”

사용자: “결과에서 뭐가 검색어랑 맞는지 모르겠어. 나머지 내용과 순서는 그대로 두고 일치한 부분만 눈에 띄게 강조하면 돼. 같은 프로젝트에서 쓸 거야.”

```text
현재 프로젝트의 검색 결과 목록에서 검색어와 일치하는 부분을 알아보기 쉽게 강조해 주세요. 많은 결과에서 어떤 부분이 일치했는지 바로 확인하는 것이 목적이에요. 현재 검색 구현을 확인하고 기존 일치 기준을 따르세요. 검색 로직, 결과 내용과 순서는 유지하고 일치한 부분의 표시를 수정하세요. 강조 방식은 기존 디자인에 맞게 정하세요.
```

목표가 드러났으므로 색상·라이브러리·개발 일정은 추가로 묻지 않는다.

## 정정과 유지 조건을 함께 반영

사용자: “검색 속도를 개선하는 프롬프트를 만들자. 기존 API는 유지해야 해.”

사용자: “아니, 속도는 괜찮아. 결과가 많아서 힘든 거야. 카테고리 필터만 추가하고 검색 순서는 그대로면 좋겠어.”

```text
검색 결과가 많을 때 원하는 항목을 좁혀 볼 수 있도록 카테고리 필터를 추가해 주세요. 기존 API와 검색 결과의 정렬 순서는 유지하세요. 필터 선택에 따라 해당 카테고리의 결과를 볼 수 있도록 하되 기존 검색 동작은 보존하세요. 구현에 필요한 프로젝트 자료가 없으면 먼저 요청하세요.
```

속도 개선은 폐기된 요구다. 기존 API 유지 조건은 번복되지 않았다. 제공 자료로 기존 API와 필터의 양립이 불가능하다고 확인된다면 그 충돌을 명확히 하고 대안을 논의한다.

## 공손한 요청과 문체를 구분

사용자: “문구 너무 딱딱해 ㅋㅋ 고객 안내문을 좀 편하게 고치는 프롬프트 써 줘. 존댓말은 꼭 유지해 주시면 좋겠어요. 원문은 거기에 붙일게.”

```text
내가 이어서 제공할 고객 안내문을 읽기 편한 자연스러운 존댓말로 다듬어 주세요. 원문의 사실과 안내 조건을 유지하고, 딱딱하거나 불필요하게 복잡한 표현을 쉽게 바꿔 주세요. 고객에게 보내는 안내문에 맞는 말투를 쓰세요. 먼저 원문을 받아 작업하세요.
```

사용자의 “ㅋㅋ”를 안내문에 넣지 않는다. 원문을 나중에 준다는 입력 절차가 이미 정해졌으므로 지금 다시 요구하지 않는다.

## 맞장구는 그 질문의 범위에서 해석

사용자: “자동 저장을 넣을지 고민 중이야. 생각을 정리해 보자. 아직 구현은 하지 마.”

AI: “작업한 내용이 사라질 걱정을 줄이는 게 목표인가요?”

사용자: “넵.”

다음 응답 예: “그럼 작업 내용이 사라지기 쉬운 상황부터 짚어 볼게요. 창을 닫거나 새로고침할 때인가요, 아니면 다른 상황인가요?”

목표 확인에 대한 응답을 기능 도입 확정으로 바꾸지 않는다. 구현 금지도 유지한다. 질문에 필요한 답이 앞선 대화에 있다면 그 정보를 활용한다.

## 실행까지 요청한 경우

사용자: “이 저장소의 README 제목 ‘시작’만 ‘빠른 시작’으로 바꿀 거야. 이 스킬로 지시를 정리하고 바로 수정까지 해 줘. 본문은 유지해.”

정리한 지시:

```text
현재 저장소의 README에서 제목 ‘시작’을 ‘빠른 시작’으로 바꾸세요. 본문은 유지하세요.
```

이어서 실제 README를 확인하고 해당 제목만 수정한다. 같은 실행 허가를 다시 묻지 않는다. 프롬프트만 주고 실행했다고 주장하지도 않는다.
