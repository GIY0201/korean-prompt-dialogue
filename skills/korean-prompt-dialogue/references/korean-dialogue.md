# 한국어 의미 해석 참고

이 문서는 해석이 갈리는 상황에서만 읽는 보조 자료다. 아래 문장은 이해를 돕기 위해 만든 예시이며, 언어학적 통계나 실험 데이터가 아니다. 표현 하나로 의도를 자동 분류하지 말고 앞뒤 발화와 작업 맥락을 함께 확인한다.

## 생략, 조사, 부정

| 표현과 맥락 | 남길 의미 | 흔한 오해 |
| --- | --- | --- |
| 회원가입 버튼을 논의한 뒤 “그거 문구만 바꿔 줘” | 회원가입 버튼의 문구 변경, 다른 요소 유지 | 어떤 버튼인지 다시 묻거나 버튼 디자인까지 수정 |
| “모바일도 적용해 줘” | 앞선 적용 대상에 모바일 추가 | 모바일로 대상 교체 |
| “모바일만 적용해 줘” | 변경 대상 모바일로 한정 | 데스크톱까지 확대 |
| “일단 모바일부터” | 현 단계는 모바일, 후속 확대는 미확정 | 데스크톱 지원 영구 금지 또는 즉시 동시 구현 |
| “검사를 통과해도 배포하지 마” | 검사 성공과 무관한 배포 금지 | 성공하면 배포 가능 |
| “추천은 빼고, 인기순은 그대로” | 추천 제거, 인기순 유지 | 추천과 인기순을 같은 기능으로 합쳐 제거 |

부정의 대상과 조건절의 범위를 확인한다. “안 바꿔도 돼”는 대개 변경 의무를 없애는 표현이며 “바꾸지 마”와 동일하지 않다. 어느 해석이 중요한지는 전체 대화에서 판단한다. “A는” 역시 대조나 화제의 기능이 문맥에 따라 달라진다.

## 높임, 공손함, 확정 여부

한국어의 주체·객체·상대 높임은 서로 구별된다. 격식적인 어미, 상대 높임, 사회적 공손함, 요청의 강도는 하나의 축이 아니다.

- “결제 방식은 꼭 그대로 두시면 좋겠어요.” → 부드러운 문체여도 강한 유지 조건을 전달할 수 있다.
- “이 버튼 문구를 ‘구매’에서 ‘구매하기’로 바꿔 주실 수 있을까요? 프롬프트로 정리해 주세요.” → 구체적인 요청이다. 단순 능력 질문으로 되묻지 않는다.
- “자동 저장을 넣으면 어떨까?” → 탐색일 수 있다. 앞서 구현 범위를 확정하는 대화였는지도 살핀다.
- “가능하면 기존 라이브러리를 써 줘.” → 선호다. 불가능한 경우까지 금지하는 절대 조건으로 강화하지 않는다.

짧은 반말도 분명하고 협력적인 요청일 수 있다. 사투리, “ㅋㅋ”, 맞춤법 변형, 영어 기술 용어는 이해에 영향을 줄 때만 확인한다. 표현을 표준화하는 일이 의도 구체화를 대신하지 않게 한다.

## 맞장구와 정정

| 앞선 발화 → 응답 | 해석할 범위 |
| --- | --- |
| “목표는 중복 입력을 줄이는 거죠?” → “넵” | 목표 이해에 대한 확인. 구현·배포 허용으로 확대하지 않음 |
| “정리한 내용으로 파일도 수정해 주세요” → 이후 작업 대화 | 이미 요청한 수정 범위에서 실행을 이어 감. 프롬프트 생성 때마다 재승인하지 않음 |
| “오류 메시지를 없애고 싶어” → “아니, 메시지는 남기고 문구를 쉽게 바꾸자는 거야” | 삭제 요구는 대체됨. 쉬운 문구로 변경, 메시지는 유지 |
| “파란색이나 초록색으로 할 수 있어요” → “색은 지금대로. 크기만 바꾸자” | 제안한 두 색은 채택되지 않음. 크기 변경만 확정 |

정정은 일부만 대체할 수 있다. 앞선 “기존 API는 유지”가 번복되지 않았다면 새 요구에도 남겨 둔다. “괜찮아요”가 수락인지 사양인지 문맥으로 풀리지 않고 결과를 바꾼다면 짧게 확인한다.

## 생각을 발전시키는 질문

추상적 평가를 관찰 가능한 장면으로 바꾼다. “정확히 어떤 요구사항인가요?”를 반복하기보다 “찾기 힘든 게 검색어를 떠올리는 과정인지, 결과에서 골라내는 과정인지”처럼 차이를 보여준다. 제시하지 않은 답도 가능하게 열어 둔다.

고민을 말하는 사용자에게는 짧은 후보나 예시를 제공할 수 있다. 다만 후보를 확정 요구로 옮기기 전에 사용자의 채택이나 수정이 있어야 한다. 이미 핵심 차이가 해소됐다면 색상 코드·도구·분량처럼 실행자가 정할 세부사항을 추가 설문으로 만들지 않는다.

## 근거와 한계

이 참고 자료의 운영 규칙은 다음 연구를 참고한 설계다. 연구가 이 스킬의 효과나 최적 질문 횟수를 검증한 것은 아니다.

- [Song & Kaiser, 2020: 한국어 생략 대명사의 문맥적 해석](https://journals.linguisticsociety.org/proceedings/index.php/PLSA/article/view/4751)
- [Kim, 2022: 상호작용에서의 높임 전환](https://benjamins.com/catalog/kl.20010.kim)
- [Ahn & Yap, 2025: ‘넵’의 상호작용 기능](https://en.semiosis.co.kr/?p=1556)
- [Clarify When Necessary, 2025](https://aclanthology.org/2025.findings-naacl.306/): 명확화의 이득과 비용을 함께 고려하는 연구

위 링크는 근거 확인용이다. 스킬을 사용할 때 매번 웹에 접속할 필요는 없다. 특정 언어·모델·과제에서 관찰된 말투 효과를 한국어 반말이나 존댓말의 보편적인 성능 우열로 일반화하지 않는다.
